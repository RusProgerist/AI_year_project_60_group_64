# Разметка состояний героев — `deepseek_labels.csv`

Многомерный профиль состояния фокусного героя для 42 текстов из `data/raw/*.json`.

## Файлы

| Файл | Назначение |
|---|---|
| `deepseek_labels.csv` | Основная разметка. `group` и `label` — по-русски, как в примере для проверки из задания. |
| `deepseek_labels_en.csv` | Те же 42 записи, `group`/`label` переведены в английские слаги. Все колонки, кроме `reason`, — ASCII. |
| `build_labels.py` | Источник истины. Генерирует оба CSV (`python3 build_labels.py`). |
| `tests/test_deepseek_labels.py` | Валидация разметки (23 теста). |
| `tests/test_tooling.py` | Регрессионные тесты вспомогательных скриптов и корпуса (13 тестов). |
| `convert_all.py` | Собирает `*.json` из `*.txt`, сохраняя метаданные (см. ниже). |
| `check_texts.py`, `check_titles.py` | Диагностика корпуса: размер, мусор, заголовки. |

### Про противоречие в ТЗ
В задании `group` и `label` перечислены в списке «строго на английском», но
в примере для проверки они по-русски (`group: социальные_трудности`,
`label: одиноко`). Чтобы удовлетворить оба требования, генерируются два файла:
основной воспроизводит пример буквально, английский — пригоден для обучения модели.

## Схема

`text_id, group, label, intensity, duration, trigger, self_awareness,
physical_symptoms, social_role, coping_style, reason`

Словари значений:

- **group / label**: `упадок_сил` {устал, выгорел, скучно};
  `социальные_трудности` {одиноко, чужой, стыдно, виноват};
  `эмоциональные_реакции` {страшно, паника, бессмысленно, злюсь, горюю}
- **intensity**: mild, moderate, severe
- **duration**: acute, chronic, episodic
- **trigger**: conflict, failure, betrayal, illness, poverty, isolation_event,
  society, work_study, loss, internal
- **self_awareness**: aware, unaware, denial
- **physical_symptoms**: sleep, appetite, pain, fatigue (через запятую) или `—`
- **social_role**: worker, intellectual, woman, child, outsider
- **coping_style**: problem_focused, emotion_focused, avoidant, aggressive,
  passive, maladaptive

## Известные ограничения корпуса

Обнаружены при чтении исходников; **не исправлялись**, так как выходят за рамки
задачи разметки, но влияют на обучение:

1. **5 файлов не содержат литературного текста** — только заголовочную страницу
   Викитеки со списком редакций: `chekhov_dyadya_vanya`, `chekhov_tri_sestry`,
   `chekhov_vishnevy_sad`, `lermontov_geroi_nashego_vremeni_vik`,
   `turgenev_otcy_i_deti_vik`. Разметка для них сделана по каноническому сюжету
   произведения, а не по содержимому файла. Перед обучением эти записи нужно либо
   перекачать, либо исключить.
2. **3 пары файлов побайтово идентичны**: `lermontov_maska_rad` = `_vik`,
   `lermontov_mcyri` = `_vik`, `turgenev_asya` = `_vik`. Дубли попарно
   продублированы в разметке (это отражено в `reason`), что даёт перевес
   соответствующим классам.
3. **`lermontov_maska_rad` содержит только список действующих лиц**, без текста драмы.
4. **Во всех файлах есть навигационный мусор Викитеки** (меню, лицензионные
   шаблоны, категории). Для обучения тексты нужно очищать.
5. **`data/annotations.csv` пуст.**
6. **`intensity` смещён к severe, `mild` не встречается ни разу.** Это честное
   свойство выборки (все тексты — кризисные сюжеты), а не ошибка разметки;
   искусственно добавлять `mild` не стал. Для сбалансированного обучения
   потребуется отдельный корпус с мягкими состояниями.

## Вспомогательные скрипты

Все скрипты считают пути от собственного расположения, поэтому их можно
запускать из любого каталога, а не только из корня репозитория.

`convert_all.py` синхронизирует текст из `data/raw/*.txt` в парные `*.json`:

* обновляет **только** поле `text` и подставляет `id`/`title` по умолчанию;
* **сохраняет** уже заполненные метаданные (`author`, `genre`, `state`,
  `source_url`, `markers`) и любые добавленные вручную поля;
* идемпотентен: файл, содержимое которого не изменилось, не перезаписывается;
* пишет атомарно (через временный файл) и восстанавливает битый JSON.

Раньше скрипт перезаписывал JSON целиком, затирая метаданные заглушками
(`author: "Неизвестен"`, пустые `genre`/`state`/`source_url`). Это поведение
закреплено регрессионными тестами в `tests/test_tooling.py`.
